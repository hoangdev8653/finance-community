# Image-to-UI Pro: Translating Mockup Images into Production Code

Use this skill whenever the user provides an image mockup (e.g. generated by GPT, DALL-E, Midjourney, or screenshot from Figma) and asks to build or update web UI components.

## Core Philosophy
An image mockup depicts **what the interface looks like at rest**, but production code must determine **how the interface behaves, adapts, and handles edge cases**.

Your job is not to literally copy raw pixel values, but to **reverse-engineer the visual design intent** and re-implement it using the project's established design tokens and components.

---

## 4-Step Translation Workflow

### Step 1: Visual Decomposition & Token Mapping
Before writing code, scan the image and identify:
1. **Primary Canvas & Surfaces**:
   - Main page background -> `bg-background`
   - Content cards / Panels -> `bg-card text-card-foreground border border-border`
   - Elevated elements / Modals -> `bg-popover text-popover-foreground shadow-lg`
   - Subtle background tints -> `bg-muted/40`
2. **Typography Hierarchy**:
   - Page Titles: `text-2xl font-bold tracking-tight text-foreground`
   - Section Headings: `text-lg font-semibold text-foreground`
   - Body copy: `text-sm text-foreground`
   - Metadata / Subtitles: `text-xs text-muted-foreground`
   - Financial figures / Percentages: `font-mono font-medium` or `tabular-nums`
3. **Icons & Controls**:
   - Replace drawn icons with matching [lucide-react](https://lucide.dev) icons.
   - Sizing: standard `w-4 h-4` or `w-5 h-5`.

### Step 2: Spacing Quantization (4px Grid)
Never use arbitrary arbitrary brackets (e.g., `p-[17px]`, `gap-[13px]`). Quantize optical space to the nearest 4px rhythm:
- Tight inline spacing: `gap-1.5` (6px) or `gap-2` (8px)
- Standard element padding: `p-3` (12px), `p-4` (16px), or `p-5` (20px)
- Container / Section spacing: `p-6` (24px) or `p-8` (32px)
- Stack spacing: `space-y-4` or `space-y-6`

### Step 3: Generating Missing UX States
Mockup images only show the "happy path". When implementing the component, you MUST supply the missing states:
1. **Loading State**:
   - Provide a companion `<ComponentSkeleton />` or inline pulse effect (`animate-pulse bg-muted rounded-md`).
2. **Empty State**:
   - When no data is available, render an empty state card with:
     - Rounded icon badge (`p-3 rounded-full bg-muted/60 text-muted-foreground`)
     - Headline (e.g. "Chưa có bài viết")
     - Helper text explaining why it's empty
     - Primary call-to-action button
3. **Micro-interactions (Hover / Active)**:
   - Clickable cards: `hover:border-primary/50 hover:shadow-sm transition-all duration-200`
   - Buttons: `active:scale-[0.98] transition-transform`
   - Table rows: `hover:bg-muted/40 transition-colors`
4. **Validation / Feedback**:
   - Destructive tokens for errors (`text-destructive`, `border-destructive`)
   - Toast notification feedback on async triggers

### Step 4: Responsive Adaptation
Mockups are almost always desktop viewports. You must proactively adapt for mobile:
- Multi-column grids: `grid-cols-1 md:grid-cols-2 lg:grid-cols-3`
- Sidebars: Collapsible sheet on mobile (`< md`), permanent on desktop (`>= lg`)
- Tables: Wrap with `overflow-x-auto` or create a mobile card view
- Controls bar: `flex flex-col sm:flex-row items-stretch sm:items-center justify-between gap-3`

## Domain-Specific Accents (Finance & Community)
1. **PnL & Metrics**:
   - Profit / Gain: `text-emerald-500 bg-emerald-500/10 border-emerald-500/20`
   - Loss / Drop: `text-rose-500 bg-rose-500/10 border-rose-500/20`
   - Warning / Caution: `text-amber-500 bg-amber-500/10 border-amber-500/20`
2. **Data Presentation**:
   - Use `tabular-nums` on financial columns and balances to prevent layout jank.
   - Separate dense rows with `divide-y divide-border/60`.
