## 2. API Client Architecture & Token Handling

```
               Browser Request
                     │
                     v
             +---------------+
             |  Axios Client |
             +-------+-------+
                     │
            Request Interceptor
      Injects Authorization: Bearer <token>
                     │
                     v
             +---------------+
             |  NestJS API   |
             +-------+-------+
                     │
            Response Interceptor
     Catches 401 Unauthorized / Errors
                     │
      ┌──────────────┴──────────────┐
      │                             │
   401 Error                    200 Success
      │                             │
      v                             v
Trigger Silent Token          Return Data Payload
Refresh / Re-authenticate
```

### Authentication Token Lifecycle
1. **Access Token Storage**: Stored in memory (React Context / Auth State Manager) to defend against XSS attacks.
2. **Refresh Token Storage**: Managed via httpOnly secure cookie or authorized storage via `/api/v1/auth/refresh`.
3. **Request Authorization**: Attached automatically via Axios Request Interceptor: `Authorization: Bearer <accessToken>`.

## 3. Standard Error Handling & Normalization

The backend returns standardized error responses generated by `SecurityExceptionFilter`:

```json
{
  "statusCode": 400,
  "error": "Bad Request",
  "message": ["title should not be empty", "categoryId must be a UUID"],
  "code": "VALIDATION_ERROR"
}
```

### Frontend Exception Interceptor Handling Rules
- **`400 Bad Request`**: Maps validation message arrays directly to React Hook Form field errors.
- **`401 Unauthorized`**: Clears in-memory access token, attempts silent refresh. If failed, redirects user to `/login?redirect=<path>`.
- **`403 Forbidden`**: Displays contextual `Alert` or error boundary: *"You do not have permission or your account requires email verification"*.
- **`429 Too Many Requests`**: Displays Toast notification: *"Rate limit exceeded. Please wait a moment before retrying."*
- **`500 Internal Error`**: Displays generic error toast while suppressing stack details.

## 4. Query Caching & State Boundaries (TanStack Query v5)

To maintain optimal performance and prevent unnecessary global state, data is split into clear boundaries:

| State Type | Management Tool | Examples |
| :--- | :--- | :--- |
| **Server State** | TanStack Query v5 | Posts feed, comments tree, user profiles, notification lists. |
| **Auth State** | React Auth Context | Current logged-in user object, permissions array, login status. |
| **Form State** | React Hook Form + Zod | Unsaved draft content, post title, form validation errors. |
| **UI State** | Zustand / Context | Sidebar expanded state, theme toggle (Dark/Light), open modal ID. |

### Query Key Hierarchy Conventions
- Posts List: `['posts', 'list', { page, limit, categoryId, tagId }]`
- Post Detail: `['posts', 'detail', slug]`
- Comments Tree: `['posts', postId, 'comments', { page }]`
- User Profile: `['users', username]`
- Notifications Feed: `['notifications', { unreadOnly }]`

## 5. Optimistic Updates Policy

To make social interactions feel instant while maintaining atomic consistency with NestJS:

1. **Reactions (`POST /api/v1/posts/:id/reactions`)**:
   - Immediately increment/decrement reaction counter and flip `userReacted` state in local cache.
   - Send background request to NestJS.
   - Rollback cache state if request fails.
2. **Follows (`POST /api/v1/users/:id/follow`)**:
   - Immediately update `following` state and increment target user's follower count.
   - Rollback if backend rejects due to account status or network error.

## 6. Presigned Media Upload Flow (Cloudinary)

Direct browser-to-Cloudinary upload protocol without exposing backend secrets:

```text
1. User selects image file in MediaUploader component.
2. Frontend calls POST /api/v1/media/signature with filename & folder type.
3. Backend returns presigned signature, timestamp, and Cloudinary API Key.
4. Frontend posts multipart form directly to Cloudinary REST API.
5. Upon Cloudinary 200 response, Frontend receives public_url & secure_url.
6. Frontend registers metadata with NestJS backend via POST /api/v1/media.
7. Registered Media ID is attached to the post DTO payload.
```
